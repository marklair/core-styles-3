# TAGS.md

This document defines the tagging system and conventions for this Obsidian vault.

## Purpose of Tags

Tags help organize and categorize notes, making them easier to find and connect. Use tags to classify notes by topic, status, type, or any other useful dimension.

## Tag Syntax

- Tags use hashtag format: `#tagname`
- Multi-word tags use hyphens: `#project-management`
- Tags can be placed in frontmatter or inline in the note body
- Tag hierarchy uses forward slashes: `#topic/subtopic`

## Tagging Rules

### 1. Use Lowercase
- Always use lowercase for tags: `#idea` not `#Idea`
- Exception: Proper nouns if absolutely necessary

### 2. Be Specific but Not Overly Granular
- Use `#machine-learning` instead of `#ml` (clarity over brevity)
- Avoid creating tags that will only apply to 1-2 notes

### 3. Use Hierarchical Tags When Appropriate
- Use nested tags for related concepts: `#programming/python`, `#programming/javascript`
- Keep hierarchies shallow (2-3 levels max)

### 4. Limit Tags Per Note
- Aim for 3-7 tags per note
- Too many tags dilutes their usefulness

### 5. Consistency
- Once a tag is established, always use the same spelling and format
- Periodically review tags and merge synonyms

## Standard Tag Categories

### Status Tags
- `#draft` - Note is incomplete or work-in-progress
- `#review` - Needs review or revision
- `#complete` - Finished and polished

### Type Tags
- `#note` - General notes
- `#idea` - Ideas and brainstorming
- `#reference` - Reference material
- `#project` - Project-related notes
- `#meeting` - Meeting notes
- `#todo` - Action items and tasks
- `#prd` - Project requirements document

### Topic Tags
Create topic tags based on your knowledge domains. Examples:
- `#math` - Mathematical concepts
- `#programming` - Programming and code
- `#research` - Research notes
- `#personal` - Personal notes

Use hierarchical tags for subtopics:
- `#math/calculus`
- `#math/linear-algebra`
- `#programming/python`
- `#programming/javascript`

### Source Tags
- `#book` - From a book
- `#article` - From an article
- `#video` - From a video
- `#course` - From a course

### Priority Tags
- `#important` - High priority
- `#urgent` - Time-sensitive

## Frontmatter vs Inline Tags

### Frontmatter Tags (Recommended)
Place tags in YAML frontmatter for cleaner notes:

```yaml
---
tags:
  - project
  - important
  - programming/python
---
```

### Inline Tags
Use inline tags when referencing concepts within the note body:
- Good for adding context to specific paragraphs
- Useful for topic-specific sections within larger notes

## Tag Maintenance

### Regular Review
- Periodically review all tags in the vault
- Merge duplicate or similar tags
- Remove unused tags
- Update tag naming for consistency

### Finding Tag Issues
- Use Obsidian's tag pane to see all tags and their usage counts
- Look for similar tags that should be merged (e.g., `#ai` and `#artificial-intelligence`)
- Identify orphan tags (used only once) and consider removal

## Tag Search and Navigation

### Using Tags
- Click any tag to see all notes with that tag
- Use search: `tag:#programming` to find tagged notes
- Combine with other search terms: `tag:#programming python`
- Use the graph view to visualize tag connections

### Tag Queries
In searches and queries:
- `tag:#programming` - Notes with this exact tag
- `tag:#programming/python` - Notes with this specific nested tag
- `-tag:#draft` - Exclude notes with this tag

## Best Practices

1. **Start Broad**: Begin with general tags and add specificity as your vault grows
2. **Document New Tags**: When creating a new major tag category, document it here
3. **Think About Discovery**: Tag notes in a way that your future self can find them
4. **Avoid Tag Explosion**: Resist creating a unique tag for every minor concept
5. **Use Links Too**: Tags complement but don't replace [[wiki-links]] between notes
6. **Review Regularly**: Set a recurring reminder to review and clean up tags

## Examples

### Good Tagging
```yaml
---
tags:
  - reference
  - programming/python
  - important
---
```

### Poor Tagging
```yaml
---
tags:
  - Ref
  - Python
  - py
  - programming
  - code
  - dev
  - important
  - must-read
  - 2026
---
```
(Too many tags, inconsistent capitalization, redundant tags)

## Reserved Tags

These tags have special meaning and should be used consistently:
- `#excalidraw` - Excalidraw drawings (auto-generated by plugin)
- `#template` - Template files
- `#archive` - Archived notes no longer actively used

## Getting Started

If you're new to tagging:
1. Start with status tags (`#draft`, `#complete`)
2. Add 1-2 topic tags that describe the main subject
3. Add a type tag if applicable (`#note`, `#idea`, `#reference`)
4. Don't overthink it - you can always refactor tags later
